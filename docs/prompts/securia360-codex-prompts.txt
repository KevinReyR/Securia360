SECURIA360 — BIBLIOTECA COMPLETA DE PROMPTS PARA CODEX
Versión: 1.0

PROPÓSITO

Este archivo divide la construcción completa de Securia360 en entregas controladas. Ejecuta los prompts en orden y abre una tarea nueva de Codex para cada uno. No combines varias etapas en una sola solicitud.

REGLAS DE USO

1. Mantén AGENTS.md en la raíz: es la especificación maestra del producto.
2. Antes de cada etapa, confirma que la anterior pasó typecheck, lint, tests y build.
3. Conserva las migraciones y el lockfile en Git.
4. No pegues service_role, secretos, contraseñas ni datos personales en prompts.
5. Usa un proyecto o rama de desarrollo antes de modificar producción.
6. Toda interpretación normativa debe quedar marcada para revisión de un profesional SST/jurídico. No copies extensamente textos normativos protegidos.
7. No aceptes una historia si RLS, integridad histórica o separación requirement/standard/methodology quedan comprometidas.

PROMPT BASE — USAR AL INICIO DE TODAS LAS ETAPAS

Lee completamente AGENTS.md y respétalo como especificación del producto. Inspecciona primero el repositorio, el estado de Git, las dependencias, las migraciones locales y remotas, el esquema Supabase, RLS, patrones y documentación existente. Preserva cambios ajenos y reutiliza componentes existentes. Resume el estado, los archivos afectados, migraciones, riesgos y plan breve antes de implementar. Trabaja solo en el alcance solicitado. Para cambios de base de datos usa migraciones versionadas, claves foráneas, constraints, índices y RLS. No expongas service_role. Verifica al terminar con typecheck, lint, tests y build; cuando corresponda prueba migraciones, RLS, aislamiento multiempresa y asesores de Supabase. Actualiza documentación y tipos generados. Si detectas un problema de seguridad crítico, corrígelo dentro del alcance antes de cerrar.

======================================================================

Identifica qué está completo, parcial o ausente en Auth, perfiles, organizaciones, miembros, RBAC, RLS, razones sociales, sedes, áreas, selector de organización, onboarding, layout, settings, dashboard, seed, pruebas, documentación y ADR. Revisa específicamente drift entre migraciones locales y remotas, grants del Data API, tablas públicas sin RLS, funciones SECURITY DEFINER, claves foráneas sin índice y secretos expuestos. Entrega un backlog priorizado P0/P1/P2 con dependencias. No modifiques código ni base de datos.

CRITERIO: diagnóstico respaldado por evidencia, sin cambios.
