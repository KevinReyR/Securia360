SECURIA360 — FUNCIONALIDADES PENDIENTES Y PROMPTS PARA CODEX
Versión: 2026-08-27

PROPÓSITO

Este documento es el inventario operativo de trabajo pendiente de Securia360. Cada entrada
indica el estado de datos real y contiene un prompt autónomo para implementar un vertical
slice. Ejecutar un prompt por tarea/PR; no combinar varios módulos.

ESTADOS DE MIGRACIÓN

- EXISTENTE: la base de datos, RLS y permisos principales ya existen; falta interfaz,
  integración, pruebas o configuración.
- PARCIAL: existen tablas relacionadas, pero falta una entidad, contrato o capacidad
  necesaria para completar el flujo.
- NO REQUERIDA: es trabajo de interfaz, calidad, configuración externa u operación.
- NO EXISTENTE: se debe diseñar y crear una migración versionada antes de implementar.

PROMPT BASE — INCLUIR AL INICIO DE CADA TAREA

Lee completamente AGENTS.md y respétalo como especificación del producto. Inspecciona
primero el repositorio, el estado de Git, las dependencias, las migraciones locales y
remotas, el esquema Supabase, RLS, patrones y documentación existente. Preserva cambios
ajenos y reutiliza componentes existentes. Resume estado, archivos afectados, migraciones,
riesgos y plan antes de implementar. Trabaja solo en el alcance solicitado. Para cambios de
base de datos usa migraciones versionadas, claves foráneas, constraints, índices y RLS. No
expongas service_role. Verifica typecheck, lint, tests y build; prueba RLS, aislamiento
multiempresa y asesores de Supabase cuando corresponda. Actualiza documentación y tipos
generados. Corrige problemas críticos de seguridad dentro del alcance. No declares
cumplimiento legal automático ni publiques o migres datos reales sin autorización explícita.

REGLA DE CIERRE

Una funcionalidad pasa a “completa” solo cuando cuenta con flujo usable, permisos
can(permission, context), RLS, auditoría, validación Zod, pruebas y documentación. Una
migración existente por sí sola nunca equivale a funcionalidad terminada.
